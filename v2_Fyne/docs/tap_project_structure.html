Repository layout

file tree

Idiomatic Go layout: cmd/ for binaries, internal/ for private packages. The three executables share internal/protocol — the single source of truth for the wire format.

the-answer-protocol/ ├── go.mod / go.sum # module: the-answer-protocol, go 1.22 ├── Makefile # deps, run-*, lint, clean ├── README.md │ ├── cmd/ │ ├── server/main.go # TCP server entry point │ ├── cli/main.go # CLI client entry point │ └── gui/main.go # Fyne GUI client entry point │ ├── internal/ │ ├── protocol/ # ★ WRITE THIS FIRST — shared contract │ │ ├── command.go # Command struct + Parse() │ │ ├── response.go # OK / ERR formatting helpers │ │ ├── event.go # EVT formatting helpers │ │ └── errors.go # RFC error code constants │ │ │ ├── server/ # rusilva- │ │ ├── hub.go # Hub actor — owns world state │ │ ├── client.go # Client — readPump / writePump │ │ └── dispatch.go # Command router + all handlers │ │ │ ├── game/ # rusilva- │ │ ├── world.go # World, Room, Player, NPC types │ │ ├── item.go # Item + TAKE / DROP logic │ │ ├── combat.go # Attack, damage formula, respawn │ │ └── quest.go # Quest state machine │ │ │ └── worldfile/ # acaldeir │ ├── loader.go # Load world.json → WorldFile structs │ └── validate.go # Referential integrity checks │ └── data/world.json # 8 rooms, 5 NPCs, 4 items, 2 quests
Dependency order — no circular imports
std lib ← worldfile ← game ← server ← cmd/*
protocol sits beside game; both server and cmd/* import it. worldfile never imports game.
02

internal/protocol — BOTH

do first

The wire contract. Every other package depends on this. Lock it down before splitting into parallel work. Any change here requires coordination.

internal/protocol/command.go both

Parses raw TCP lines into typed Command structs.

  • Parse(line string) (Command, error)splits verb + args, uppercases verb
  • (Command) String() stringre-serialises for logging
internal/protocol/response.go both

Formats OK and ERR response lines sent back to clients.

  • OK(data string) string"OK [data]\n"
  • OKf(format, args) stringSprintf variant
  • OKJson(v any) stringmarshals to JSON, wraps in OK
  • Errf(code int, msg string) string"ERR 301 NO_EXIT\n"
internal/protocol/event.go both

Formats all async EVT lines pushed from server to clients.

  • RoomPresenceEnter(username) stringEVT ROOM PRESENCE ENTER
  • RoomPresenceLeave(username) stringEVT ROOM PRESENCE LEAVE
  • RoomChat(username, msg) stringEVT ROOM CHAT
  • GlobalChat(username, msg) stringEVT GLOBAL CHAT
  • GroupInvite / GroupJoin / GroupLeave / GroupChatEVT GROUP *
  • StatsPlayers(count int) stringEVT STATS players=N
internal/protocol/errors.go both

RFC 42TAP error code and message constants — no magic numbers.

  • ErrCodeNameInUse = 201NAME_IN_USE
  • ErrCodeNoExit = 301NO_EXIT
  • ErrCodeItemNotFound = 404ITEM_NOT_FOUND
  • ErrCodeNPCNotHostile = 405NPC_NOT_HOSTILE
  • ErrCodeNoQuestAvailable = 406NO_QUEST_AVAILABLE
  • … (all RFC codes)see file for full list
03

internal/server — rusilva-

engine

The concurrency core. Three files, three concerns: the actor loop, the per-client I/O, and the command router. They are tightly coupled — rusilva- owns all three.

internal/server/hub.go rusilva-

The Hub is the ONLY goroutine that mutates game state. Processes one event at a time via select{} — no mutexes needed on World structs.

  • NewHub(world *game.World, log *slog.Logger) *Hubinitialise channels + maps
  • (Hub) Run()main select loop: register / unregister / commands — call as goroutine
  • (Hub) broadcast(roomID, msg, exclude)send to all clients in one room
  • (Hub) broadcastAll(msg)send to every connected client
  • (Hub) broadcastGroup(groupID, msg)send to group members only
  • (Hub) removeClient(c *Client)remove player from world THEN broadcast LEAVE
  • (Hub) updatePlayerCount()EVT STATS to all after connect/disconnect
internal/server/client.go rusilva-

One Client per TCP connection. Runs two goroutines so reads and writes never block each other.

  • newClient(conn, hub, log) *Clientwrap accepted connection
  • (Client) readPump()bufio.Scanner loop → hub.commands channel
  • (Client) writePump()drain send channel → write to TCP
  • (Client) safeSend(msg)non-blocking send; disconnect if buffer full
internal/server/dispatch.go rusilva-

Maps every RFC verb to a handler. All handlers run inside Hub's goroutine.

  • (Hub) dispatch(c, cmd)look up verb → call handler → safeSend response
  • handleConnect / handleQuitsession lifecycle
  • handleLook / handleMove / handleWhoworld exploration
  • handleChatGLOBAL / ROOM / GROUP scopes
  • handleGroup→ Create / Invite / Join / Leave sub-handlers
  • handleTake / handleDrop / handleInventoryitem management
  • handleTalkNPC dialogue → JSON response
  • handleAttack / handleStatuscombat
  • handleQuest / handleQuestsquest system

internal/game — rusilva-

domain logic

Pure game domain — no networking, no I/O. These packages are easy to unit-test in isolation. The Hub calls into them; they never know about TCP.

internal/game/world.go rusilva-

Core types and world-level operations. Mutated only by the Hub — no mutexes.

  • World, Room, Player, NPCbase structs — all mutable game state
  • NewWorld(wf *worldfile.WorldFile) *Worldconverts file schema → runtime structs
  • (World) GetRoom(id) *Roomnil if not found
  • (World) GetPlayer(username) *Playernil if not found
  • (World) AddPlayer(username) (*Player, error)place at StartRoom
  • (World) RemovePlayer(username)remove from room + world map
  • (World) MovePlayer(player, direction) (*Room, error)returns new room or ERR NO_EXIT
  • (World) PlayersInRoom(roomID) []stringfor broadcast targeting
  • (World) TotalPlayers() intfor WHO + EVT STATS
  • (World) NPCInRoom(room, name) (*NPC, bool)case-insensitive name match
internal/game/item.go rusilva-

Unique item instances — no duplication. TAKE removes from room; DROP returns to room.

  • Item{ ID, Name }
  • TakeItem(room, player, identifier) (*Item, error)move floor → inventory
  • DropItem(player, room, identifier) (*Item, error)move inventory → floor
  • FindItem(items, identifier) (*Item, bool)ID or name match, case-insensitive, multi-word
internal/game/combat.go rusilva-

One ATTACK = one round. No persistent combat state. Document formula in README.

  • CombatResult{ AttackerHP, TargetHP, Damage, CounterDmg, Status, Defeated, PlayerDied }
  • Attack(player, room, npcName) (*CombatResult, error)one full round
  • calculateDamage() intdefine formula here
  • RespawnPlayer(world, player)start room, 50% MaxHP
internal/game/quest.go rusilva-

State machine per player: NotStarted → Active → Completed.

  • QuestState (int)NotStarted / Active / Completed
  • QuestDef{ ID, Description, Type, TargetID, Reward }
  • PlayerQuest{ Def, State, Progress }
  • GetQuestFromNPC(player, room, npcName) (*QuestDef, error)nil if none / already done
  • StartQuest(player, def)NotStarted → Active
  • CheckCompletion(player, pq) boolvalidates objectives met
  • CompleteQuest(world, player, pq) errorgrant reward → Completed
  • ListQuests(player) []*PlayerQuestfor QUESTS command

internal/worldfile — acaldeir

data layer

Reads and validates data/world.json. Called once at startup. If validation fails, the server must exit with a clear error before accepting any clients.

internal/worldfile/loader.go acaldeir

File schema structs (1:1 with JSON keys) + parsing logic.

  • WorldFile, RoomDef, ItemDef, NPCDef, QuestDefJSON schema structs with tags
  • Load(path string) (*WorldFile, error)os.ReadFile → parseJSON
  • parseJSON(data []byte) (*WorldFile, error)json.Unmarshal + error check
internal/worldfile/validate.go acaldeir

Checks every reference before the server accepts clients. Fail early, fail clearly.

  • Validate(wf *WorldFile) errorcalls all check* helpers in order
  • checkStartRoom(wf) errorstart_room exists in rooms map
  • checkExits(wf) errorevery exit points to existing room
  • checkItemRefs(wf) errorroom item IDs exist in items table
  • checkNPCRefs(wf) errorroom NPC IDs exist in npcs table
  • checkQuestRefs(wf) errorNPC quest_ids exist in quests table
  • checkMinimums(wf) error≥8 rooms, ≥3 NPC roles, ≥4 items, ≥2 quests

cmd/ — entry points

binaries
cmd/server/main.go rusilva-

Wires everything together: load world → create Hub → listen TCP → accept connections.

  • main()worldfile.Load → Validate → NewHub → go hub.Run() → listenAndServe
  • listenAndServe(ctx, ln, hub, log)Accept loop — go newClient(conn,hub,log).readPump()
cmd/cli/main.go rusilva-

Two goroutines: one reads from server, one reads from stdin. Neither blocks the other.

  • main()net.Dial → go readLoop → writeLoop
  • readLoop(conn, done chan)server → stdout; closes done on EOF
  • writeLoop(conn, done chan)stdin → server; exits on done
cmd/gui/main.go acaldeir

Fyne desktop client. Opens its own window, dials the TAP server over TCP, runs the Fyne event loop on the main goroutine and a network reader goroutine that pushes lines into a channel for the UI to consume.

  • main()net.Dial → app.New() → build layout → go readLoop → ShowAndRun()
  • readLoop(conn, events)bufio.Scanner over TCP, push each line to events chan
  • sendCommand(conn, verb, args...)format via internal/protocol and write to conn
  • buildRoomPanel()name, description, exits, items, NPCs, players-in-room
  • buildChatPanel()GLOBAL / ROOM / GROUP tabs + input (separate from log)
  • buildInventoryPanel()item list + DROP button
  • buildActionBar()buttons mapping 1:1 to LOOK / MOVE / TAKE / DROP / TALK / ATTACK / STATUS / QUEST / QUESTS
  • buildStatusBar()player name, HP, players in room, players on server
  • applyResponse(line)route OK/ERR by verb of last command sent
  • applyEvent(line)route EVT by category (ROOM / GLOBAL / GROUP / STATS)

Package dependency graph

no cycles

Read the arrows as "imports". game imports worldfile (to convert file structs into runtime structs). Nothing imports server or cmd — they are the leaves.

// bottom → top: each level imports the one below cmd/server ──imports──▶ server, game, worldfile cmd/cli ──imports──▶ protocol (just formatting helpers) cmd/gui ──imports──▶ stdlib only (net/http) server ──imports──▶ game, protocol game ──imports──▶ worldfile protocol ──imports──▶ stdlib only (errors, fmt, encoding/json) worldfile ──imports──▶ stdlib only (encoding/json, os, fmt)
No circular imports — ever
Go refuses to compile circular imports. If you feel tempted to import game from worldfile, stop and redesign. The current layout avoids this: worldfile defines file-schema structs; game.NewWorld() converts them into runtime structs.
